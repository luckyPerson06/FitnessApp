# Fitness App (Grain)

[![SonarQube](https://img.shields.io/badge/SonarQube-Анализ%20кода-blue?logo=sonarqube)](https://sonarcloud.io/summary/overall?id=luckyPerson06_FitnessApp&branch=main)

## 📋 О проекте
Backend-приложение для управления фитнес-клубом. Реализует полный цикл работы с клиентами, тренерами, абонементами и расписанием тренировок.

## 🏗️ Функциональность

### 👥 Управление клиентами
- Регистрация и управление профилями
- Привязка абонементов
- История посещений

### 👨‍🏫 Управление тренерами
- Профили и специализация
- Расписание тренировок
- Назначение типов тренировок

### 📅 Расписание
- Создание тренировочных сессий
- Проверка пересечений у тренеров
- Отслеживание свободных мест

### 🎟️ Абонементы
- Различные типы (LIMITED/UNLIMITED)
- Привязка к типам тренировок
- Контроль использования

### ✅ Посещения
- Запись на тренировки
- Отметка посещений
- Статистика по часам

## 🚀 Новые возможности

### 🔍 Расширенный поиск с фильтрацией
- Поиск тренировок по тренеру и дню недели
- JPQL и Native query реализации
- Пагинация результатов (Pageable)

### ⚡ Кэширование запросов
- In-memory кэш на основе ConcurrentHashMap
- Составной ключ из параметров запроса (тренер, день, страница, размер)
- Автоматическая инвалидация при изменении данных
- Мониторинг HIT/MISS через логирование

### 🔄 Инвалидация кэша
- Очистка при создании/обновлении/удалении тренировок
- Инвалидация по тренеру (все кэшированные запросы для него)
- Поддержка транзакционной целостности через self-injection

## 🛠️ Технические особенности

### Архитектура
- Java 17 + Spring Boot 3.3.5
- JPA/Hibernate с PostgreSQL
- MapStruct для маппинга DTO
- Flyway для миграций

### Модель данных
- 6 связанных сущностей
- Связи OneToMany и ManyToMany
- Индексы для оптимизации запросов
- Версионирование через @Version

### Оптимизация запросов
- Пагинация с Pageable
- JPQL и Native запросы
- Сравнение производительности
- Проблема N+1 и её решение через JOIN FETCH

### Кэширование
- In-memory индекс (ConcurrentHashMap)
- Составной ключ с правильными equals/hashCode
- Автоматическая инвалидация при изменениях
- Логирование HIT/MISS

### Демонстрационные возможности
- Проблема N+1 и её решение через JOIN FETCH
- Атомарные операции с rollback (с @Transactional)
- Проверка пересечений расписания
- Два типа запросов (JPQL и Native)
- Работа кэша (HIT/MISS логи)
